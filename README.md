# Home Currency

> A travel-first currency converter built to reduce the mental friction of translating prices away from home.

Home Currency is a mobile app designed for travelers who want a fast, practical way to understand prices in both directions:

- **Away** — convert from your home currency into the destination currency.
- **Home** — convert a local price back into the currency that feels familiar.

The app is being developed as an independent product and technical portfolio project.

---

## ✨ Highlights

- Two-way **Home / Away** currency conversion
- Separate calculator for each currency field
- **Use Result** workflow that sends calculator output directly into the converter
- Cached exchange rates for offline use
- Visible **Rates Updated** date
- Automated daily exchange-rate refresh
- Provider fallback strategy
- Flutter mobile interface

## 🧭 Why Home Currency?

Most currency tools are built around a simple conversion transaction.

Travelers often think about money in two different directions instead:

| Question | Home Currency mode |
|---|---|
| "What is $50 worth where I'm going?" | **Away** |
| "This costs €38 — what does that feel like at home?" | **Home** |

Home Currency keeps both directions readily available so the traveler does not have to repeatedly reverse currencies or reach for a separate calculator.

## 🔄 Exchange-Rate Pipeline

Home Currency uses a scheduled data pipeline instead of querying a third-party exchange-rate API for every conversion.

1. **EventBridge** triggers the refresh process on a daily schedule.
2. **AWS Lambda** retrieves the latest exchange-rate data.
3. The response is normalized into the Home Currency data format.
4. The generated `rates-latest.json` file is written to **Amazon S3**.
5. The file is made available to the mobile app through a CDN endpoint.
6. The app stores the latest successful download locally for offline use.

This approach creates a stable boundary between the app and external data providers.

---

## 📴 Offline Behavior

Travel connectivity is not always reliable.

Home Currency keeps the latest successfully retrieved exchange-rate data on the device so core currency conversion remains available when the network is unavailable.

The interface also shows when the rates were last updated, allowing the traveler to understand the age of the cached data.

## 🧮 Integrated Calculators

Travel prices often require a calculation before conversion.

Common examples include:

- discounts
- taxes
- tips
- quantities
- splitting a total
- combining several purchases

Each currency field therefore has access to its own calculator.

The calculator's **Use Result** action sends the calculated value directly back into the conversion workflow, avoiding manual copy-and-paste steps.

## 🗂️ Data Design

Exchange-rate data uses a versioned schema.

Current schema:

```text
schemaVersion: 1
```

Versioning provides a compatibility boundary between the cloud-generated rate file and future versions of the mobile application.

## 🧠 Engineering Decisions

### Centralized rate retrieval

The mobile application consumes data produced by the Home Currency backend instead of being tightly coupled to one external exchange-rate provider.

Benefits include:

- easier provider replacement
- fallback-provider support
- consistent JSON structure
- controlled refresh frequency
- reduced third-party API traffic

### Local caching

Exchange rates do not require second-by-second updates for this use case.

Caching the latest successful rate download improves resilience while keeping the app useful during intermittent or unavailable connectivity.

### Two conversion directions

The interface treats **Home** and **Away** as separate travel tasks instead of making the user repeatedly swap currencies.

### Integrated calculation workflow

Calculator results flow directly into conversion fields, reducing repetitive steps during actual travel use.
